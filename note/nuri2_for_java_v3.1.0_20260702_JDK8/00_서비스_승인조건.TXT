#★[누리2 모듈 설명]
###########################################################################################################################################################
* [누리2][Nuri2]는 독립 실행형 데몬입니다.
 - Java Library가 아닙니다.
 - 상시 기동 유지 해야합니다.
 - ★ 메시지 테이블(NRMSG_DATA)에 입력된 데이터를 처리하는 방식
 - ★ 입력, 조회, 통계등 기능 개발이 필요합니다.
 - DB 방식이므로 가능하면 DBA 권한 필요 합니다
 - 테이블 및 Sequence를 자동 생성됩니다. 수동생성 권장하지 않습니다.
 - 모듈 기동 및 데이터(입력예제) 입력 결과 회신등 처리 과정에 대한 모든 로그를 남깁니다.

* [★]방화벽 오픈이 되면 연동 테스트를 하실 수 있습니다
 - 모듈 기동 및 데이터(입력예제) 입력 결과 회신
 - 데이터 검증이기 때문에 실제 메시지 발송은 안됩니다.

#[★]서비스 승인절차 안내
###########################################################################################################################################################
* SMS, MMS(LMS), ALT(카카오), RCS 별도 승인
 - 테스트 이력 확인
 - 모바일메시지는 SMS/MMS를 기본으로한 시작된 서비스 입니다.
 - SMS만 테스트시 SMS만 승인(발송)처리
 - SMS/MMS(LMS) 발송이력 있으면 SMS/MMS(LMS) 발송처리
 - ALT 단독 승인 불가, 실패시 문자(XMS) 처리 필수.
 - RCS 단독 승인 불가, 실패시 문자(XMS) 처리 필수.

**[유의] 개발용, 개발서버는 승인 불가.
 - 기관에 운영중인 개발기(개발서버)는 승인 불가
 - 최종 승인까지는 운영장비도 모두 테스트배드로 연동 필요.

1)* 필수테스트 사항(접수)
 - 모든 메시지는 한글 메시지 발송을 기본으로 함.
 - xMS(문자)는 90 Byte(SMS),91 Byte(LMS)구간 테스트 필수,
   ALT 실패시 xMS(문자) 경우도 동일 확인 필요.
 - 메시지별 500건 이상 메시지 전송, 접수 성능 확인
  (Aagent의 순수 성능 확인, 대량메시지를 일괄 입력 후 전송,
  1초에 30건이상 접수가 되어야 정상, 초당 30건일때 한 시간에 10만건 처리 )
 - ALT, RCS 사용 기관은 실패시 xMS(문자)로 처리 필수
  (승인 후 ALT나 RCS만 사용은 가능 하지만 권장하지 않음)
* [메시지 우선순위전송] 방식 1~3순위 지정 가능
   예) ALT(1순위) > xMS(2순위) : 동일 MSG_KEY 접수이력 확인
   예) RCS(1순위) > xMS(2순위) : 동일 MSG_KEY 접수이력 확인
   예) ALT(1순위) > RCS(2순위) > xMS(3순위) : 동일 MSG_KEY 접수이력 확인
* 중요: 메시지 우선 순위방식은 기관 시스템의 부하 및 G/W 부담을 줄이는 방식입다.
  (ALT/xMS 동시 발송처리는 금지 사항 입니다. )

2)* 각메시지별, 최소 최대크기 확인
 - SMS(90byte) : 한글2byte 최대 45자.

- 마지막에 넣었지만 최우선 접수 요청시에는 MSG_PRIORITY를 7로 입력.
- MSG_TYPE 마다 각각 우선순위를

2) 메시지 상태값(결과 확인)
* MSG_STATE(메시지상태) =  1:입력(전송대기),  3:발송준비(QUE 수집), 5:결과대기(G/W접수 완료, 발송 결과 대기, SMS/RCS:24시간, MMS:72시간), 6:결과처리 완료(결과회신)

[*중요*] 성공 실패는 MSG_STATE 와 RSLT_CODE 값을 조합해서 분석이 필요

* 성공은 아래와 같습니다.
예) [성공]: MSG_STATE='6' AND (RSLT_CODE='0' OR RSLT_CODE='1000')

* 실패는 아래와 같습니다.
예) [실패]: MSG_STATE='6' AND (RSLT_CODE<>'0' OR RSLT_CODE<>'1000') : 상태 코드 NURI2_NRMSG_RSLT 코드 조회

*아래는 MSG_STATE 상태 설명
[완료] : MSG_STATE='6' : 성공 또는 실패등 명확한 결과가 확인됨
[대기] : MSG_STATE='5' : 발송 결과 대기 상태, XMS(문자)로 처리된 경우 대기 시간이 SMS:24시간, MMS(LMS):72시간 대기시간이 필요함.
[큐잉] : MSG_STATE='3' : 메시지를 Queue에 적재
[입력] : MSG_STATE='1' : 메시지 입력 상태

[★][결과코드 분석 방법: 기타]
 - MSG_STATE='6' 성공, 실패등 결과가 확인 된 경우 RSLT_CODE로 분석
 - RSLT_CODE는 3자리코드, 1리 코드, 4자리 코드등이 있습니다
 - * 3자리 코드: 1XX, 2XX, 3XX, 4XX, 5XX, 9XX가 있습니다. 이 경우는 누리2 내부실패로 발송이되지 않은 상태
 - * 1자리 코드: 메시지 서버, 또는 이통사에서 회신된 결과 코드입니다.
 - * 4자리 코드: 메시지 서버, 카카오, RCS 결과코드

#** 결과코드 분석 : MSG_STATE, RSLT_CODE
###########################################################################################################################################################
1. 메시지 상태(MSG_STATE) 안내
-----------------------------------------
* MSG_STATE = 1 : [입력] : 메시지 입력 상태, 메시지 입력 기본 값 다른값 입력시 아무런 동작을 하지않음
* MSG_STATE = 3 : [큐잉] : 메시지를 Queue에 적재, 발송처리 대상 조회 후 발송 QUEUE에 적재 한 상태
* MSG_STATE = 5 : [대기] : 메시지 G/W로 접수완료, 발송 결과 대기 상태
 - xMS(문자:SMS/MMS)로 처리된 경우 대기 시간이 SMS는 24시간, MMS(LMS):72시간 대기 시간이 필요함.
 - 이통사로부터 결과가 아직 회신되지 않은 상태이므로 성공도 아니고, 실패도 아님
* MSG_STATE= 6 : [완료] : 이통사 및 GateWay로 부터 결과 회시, 성공 또는 실패등 결과가 확정됨
-----------------------------------------
2. 결과 분석 : 성공 실패는 'MSG_STATE' 와 'RSLT_CODE' 값을 조합해서 분석이 필요
-----------------------------------------
* 성공은 아래와 같습니다.
예) [성공]: MSG_STATE=6 AND RSLT_CODE IN ('0','1000')

* 실패는 아래와 같습니다.
예) [실패]: MSG_STATE=6 AND RSLT_CODE NOT IN ('0','1000')
  - RSLT_CODE는 결과코드테이블( NRMSG_RSLT OR NURI2_NRMSG_RSLT) 코드 조회

-----------------------------------------
3. 결과코드 분석 방법[기타] :  MSG_STATE=6 인경우 RSLT_CODE 자릿 수로 분석진행
-----------------------------------------
 * RSLT_CODE는 3자리코드, 1리 코드, 4자리 코드등이 있습니다
 1) LENGTH(RSLT_CODE)=3 : 3자리 코드
  - 1XX, 2XX, 3XX, 4XX, 5XX, 9XX가 있습니다. 이 경우는 누리2 내부실패로 발송이되지 않은 상태
 2) LENGTH(RSLT_CODE)=1 : 1자리 코드
  - xMS(SMS/MMS/LMS)로 처리된 결과, 이통사로부터 회신된 결과 코드입니다.
 3) LENGTH(RSLT_CODE)=4 : 4자리 코드
  - 알림톡(ALT, 카카오) 및 RCS 서버로 부터 받은 결과코드

#* 누리2 테이블 설명
###########################################################################################################################################################
* [중요] Nuri2의 4개 이상의 테이블을 자동 생성합니다.
* 아래는 기본 테이블 입니다.
* 최초 2개 테이블 생성
------------------------------------------
1.[필수][2] : 자동생성 최초 1회
NRMSG_DATA(NURI2_NRMSG_DATA) : 메시지 전송 테이블, 발송하려는 메시지를 입력
NRMSG_RSLT(NURI2_NRMSG_RSLT) : 전송 결과 코드정보 테이블, 해당 테이블에 RSLT_CODE 를 조회 하여 RSLT_EXPLA 참고, 값 수정 가능
------------------------------------------
2.[필수][추가] : NRMSG_DATA(NURI2_NRMSG_DATA), 월단위, 연단위, 설정에 따른 테이블 자동생성
NRMSG_LOG(NRMSG_LOG_YYYYMM) : MSG_STATE='6'(상태완료)인 메시지를 저장하는 테이블(NRMSG_DATA 와 컬럼(필드)이 같음), (NURI2_)NRMSG_DATA 에서는 삭제 (NURI2_)NRMSG_LOG(_YYYYMM) 로 이동됨.
 - 실시간, 배치(5) 모드가 있음
 - 로그(NRMSG_LOG) 테이블은 MSG_STATE=6 인 데이터가 있을 때 생성 됩니다. 모듈 기동시 없을 수 있습니다.
------------------------------------------
3.[선택][추가]: 이중화 설정시 자동생성.
NRMSG_DUPLEX(NURI2_NRMSG_DUPLEX) : 이중화를 위한 테이블(nuri2.conf 설정한 경우 생성, duplex_switch = ON)(*절대 수정불가)
