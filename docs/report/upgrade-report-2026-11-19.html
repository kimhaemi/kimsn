1. 배경과 결론

2026-11-17 OpenJDK에서 인증 없이 원격으로 서버를 장악할 수 있는 취약점 Java4Shell (CVE-2026-114938, CVSS 9.2)이 공개되었다. 패치된 Java 25를 쓰려면 프레임워크도 함께 올려야 하므로 Java·Spring Boot·빌드 도구를 모두 전환했다.
결론: 개발 PC와 로컬 DB에서 할 수 있는 테스트는 모두 마쳤고 통과했다 (업그레이드로 생긴 화면 오류 1건은 발견 즉시 수정). 운영 배포 전에 운영 환경에서만 가능한 확인(SFTP 호환성, 운영 DB 관리자 계정, 서버 JDK 설치)과 노출된 비밀번호 교체가 남아 있다.

6. 작업 중 발견하고 조치한 문제

  • Daemon 기동 실패 — 설정 import의 classpath*:가 Boot 4에서 오류. 기동 테스트로 발견해 수정
  • 권한 상승 — 회원 생성 화면이 권한 값을 브라우저에서 보내 USER가 관리자 계정을 만들 수 있었음 → 관리자 전용으로 차단
  • 로컬 DB 구조 차이 — 로그인 후 500 오류. 코드가 아니라 로컬 DB가 옛 구조였음 → 맞춤 SQL 작성·적용 (업그레이드와 무관)
  • 화면 경고 — Thymeleaf 옛 표현식 경고(화면마다 2건) → 0건
  • 문자 결과 화면 오류 — Thymeleaf 3.1 보안 제한으로 화면이 중간에 끊김(응답은 200이라 눈에 안 띔) → 표현식 수정
  • 위험한 테스트 예시 — 문서의 Daemon 테스트 설정대로 하면 나머지 관측소에 실제 SFTP 접속 → 예시 수정·경고 추가
  • 새로 발견한 평문 비밀번호 — 참고 SQL 파일 1개 (S3에 추가)
  • 문서 이력의 민감값 — 테스트 주소·계정 이름을 Git 이력에서 제거 (push 전)

7. 운영 배포 전 반드시 할 일

  • 노출된 비밀번호 교체 (S2~S4) — 가장 시급. Git 이력에 남아 있음
  • 관측소 SSH 버전 확인 — 새 SFTP 라이브러리는 옛 암호 방식을 기본 거부. OpenSSH 7.2 미만이면 접속 실패 가능
  • 운영 DB 관리자 계정 확인 — ADMIN 1명 이상, 권한 빈 값 0건
  • 운영 서버 JDK 25.0.5.1 이상 설치 — 변경 이력에 CVE-2026-114938 포함 확인, 기존 JDK 11은 되돌리기용으로 보관
  • 순차 교체 — TDWR → SDR → SDR_B → RDR → RDR_B → 웹, 단계마다 한 주기 이상 관찰
